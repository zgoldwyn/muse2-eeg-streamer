# End-to-End Session Workflow
| Stage | Participant action | Operator action | What the interface displays | What the system records | Potential failure cases |
| ----- | ------------------ | --------------- | --------------------------- | ----------------------- | ----------------------- |
| Begin session | Wait for operator | Create a new session using a new custom session ID rather than the participant's name | New session screen displaying session ID | Session ID and participant name (separately) | Session ID isn't unique, participant name is incorrect |
| Connecting headset | Wait for operator | Connect the Muse headset | Muse headset connection status | Status message saying "headset connected" | Headset does not connect |
| Check EEG channel status | Put on headset and adjust as instructed by operator | Help participant adjust headset until all four channels (TP9, AF7, AF8, TP10) are successfully recognized | Channel signal strength/connection status, live input from each channel | Status message for each individual channel successfully connecting | One or more channels fails to connect, one or more channels has too weak of a signal for meaningful analysis |
| Confirm that the system is ready to record | Wait for operator | Double check that the headset is connected and all four channels are reading strong | Muse headset connection status, channel signal strength/connection status, live input from each channel | Nothing new | Headset or EEG channel status changes since the first time they connected |
| Start recording | Wait for operator | Start recording | Start button, timer, headset and channel connection statuses, live channel input | "Recording started" message | Start button doesn't actually start the recording |
| Guide participant through planned prompts | Listen to the operator's instructions and follow their directions | Give participant instructions based on planned prompts | Nothing new | Nothing new | Operator instructions are unclear or participant performs instructions incorrectly, recording is interrupted | 
| Add observer markers when relevant events are observed | Continue following the operator's instructions | If there is a noticeable spike in brain activity at any point, add an observer marker via the interface | Add observer marker button | Status message saying the timestamp at which a observer marker was created, number the observer marker | Observer marker is not added, observer marker is added at the incorrect timestamp, operator clikcs the wrong marker |
| Pause, stop, or abort session when necessary | Do not continue onward if the operator instructs you to stop | Clearly instruct the participant to stop following the last instruction they were given and remove the headset from their head | Pause/stop recording button | Timestamp at which recording was paused/stopped | Pause/stop button doesn't work, application is interrupted, application crashes |
| Review | Wait for operator | Review the session and add any final notes/markers as necessary | Various playback buttons | Nothing new | The session fails to save or saves in the wrong location |
| Save session | Wait for operator | Save the session and check if the file was saved properly | "Save session" button  | Filepath for saved session | Saved session cannot be replayed |

# When to Pause/Abort a Session
If the participant expresses discomfort with the headset or any of the instructions being asked, pause the recording. Address the participant's problem as best you can and ask them if they are comfortable enough to continue. If they say no, abort the session. If they say yes, unpause the recording and continue. 

If the participant explicity requests to stop, abort the session. 

If the headset loses connection or the recording fails in any way, abort the session.
